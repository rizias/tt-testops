# tt-testops

**Читающий шлюз к Allure TestOps.** Достаёт тест-кейсы и отдаёт их как Markdown, JSON или самодостаточную
HTML-страницу, попутно отмечая кейсы, которые пора переписать. Командная строка и библиотека поверх одного
движка.

> [!IMPORTANT]
> Инструмент **никогда и ничем не пишет в TestOps**. Любая команда — только чтение.

Полный список возможностей — [docs/features.md](docs/features.md).

## Установка

Нужен **Node.js 22+**.

```bash
npm install --global @rizias/tt-testops
tt-testops init
tt-testops config init
```

`config init` создаёт раскладку настроек в `~/.tt-testops/` и заготовки `profile.json` и
`credentials.json`. Как их заполнить и что значит каждое поле — [docs/settings.md](docs/settings.md).

## Быстрый старт

Дальше — один кейс на экран:

```bash
tt-testops case <ид-кейса>
```

## Настройка

Проверить, что подхватилось: `tt-testops config`. Каждое поле показано со значением и источником
(`flag`, `env`, `file`, `default`); секрет `testops.token` — только признаком «задан» или «не задан»,
само значение команда не печатает никогда.

| Поле | Что меняет | Переменная | Умолчание | Где взять значение |
|---|---|---|---|---|
| `description` | заметка о контуре | — | — | по желанию |
| `servers.testops.kind` | вид сервера, значение `"allure-testops"` | — | `"allure-testops"` | не меняется |
| `servers.testops.baseUrl` | адрес сервера TestOps | `TT_TESTOPS_SERVER_TESTOPS_BASE_URL` | обязателен | адресная строка браузера |
| `testops.token` (в `credentials.json`) | API-токен | `TT_TESTOPS_SERVER_TESTOPS_TOKEN` | обязателен | TestOps: профиль → API tokens |
| `defaultProject` | проект по умолчанию, когда нет `--project` | `TT_TESTOPS_DEFAULT_PROJECT` | — | номер проекта в адресе его страницы |
| `projects` | номер → имя, чтобы писать `--project WEB` | нет | — | `tt-testops projects` |
| `people` | учётка сервера → как показывать | нет | — | по желанию |
| `trees` | рабочее дерево разделов проекта — названием, как в интерфейсе TestOps: `{ "<ид>": "<название>" }`; `"none"` — путь не нужен. Деревьев несколько, а выбора нет — `case` и `list` не начинают выгрузку | нет | — | `tt-testops trees` |
| `limits.timeoutSec` | секунд ждать ответ | `TT_TESTOPS_TIMEOUT_SEC` | `30` | — |
| `limits.maxCases` | предел кейсов на проект за вызов | `TT_TESTOPS_MAX_CASES` | `100` | — |
| `limits.concurrency` | общий предел одновременных обращений к TestOps | `TT_TESTOPS_CONCURRENCY` | `8` | — |
| `limits.retries` | повторов после первой временной ошибки; `0` отключает | `TT_TESTOPS_RETRIES` | `3` | — |
| `formatFile` | путь к JSON-профилю оформления вывода | `TT_TESTOPS_FORMAT_FILE` | — | см. [docs/format.md](docs/format.md) |

Профиль выбирается флагом `--profile`, переменной `TT_TESTOPS_PROFILE` или полем `profile` общего файла
`config.json`, иначе — `default`. Подкоманды `config`, каталоги, примеры `profile.json`/`credentials.json` —
[docs/settings.md](docs/settings.md).

## Команды

| Команда | Что делает |
|---|---|
| `case <id>` | один кейс по ID → Markdown (или `--format json`) |
| `list <запрос>` | все кейсы по запросу → Markdown каждого + сводка проблемных |
| `audit <запрос>` | только список проблем по запросу (старый формат, пустой сценарий…) |
| `count <запрос>` | сколько кейсов подходит под запрос — одно число, без выгрузки |
| `fields [имя]` | без имени — обзор полей и слоёв проекта; с именем — его значения и число кейсов; `--find <текст>` — поиск по проекту |
| `link <запрос>` | ссылка на фильтр TestOps по запросу — открыть в браузере или переслать коллеге |
| `projects` | согласованный список проектов из конфигурации и что есть на сервере сверх него |
| `trees` | деревья разделов проекта: из каких полей собраны и какое сейчас рабочее |
| `cache [clear]` | что лежит в локальном хранилище; `clear` — очистить |
| `attachments <id>` | положить вложения кейса файлами и напечатать пути; `--out <каталог>` |
| `config [init\|use\|profiles]` | что действует сейчас; создать настройки, сменить профиль, список |
| `setup [путь]` | как поставить инструмент именно в этот проект; ничего не меняет |
| `init [путь]` | разложить скилл, чтобы агент знал про инструмент; спросит, куда именно |
| `update` | обновить пакет до последней опубликованной версии через npm |
| `--version` | версия установленного пакета |

Опции — `--project`, `--limit`, `--format markdown|json|html|raw`, `--out`, `--no-marks`, `--tree`,
`--refresh`, `--rql`/`--rql-file`, `--find`. Разбор каждой команды с примерами, несколько проектов в одном
вызове, язык AQL и устойчивость запросов к сети — [docs/commands.md](docs/commands.md) и
[docs/aql.md](docs/aql.md).

## Контракт вывода

Markdown кейса заморожен побайтно: жирная шапка `# **{имя}** (ID: {номер})`, литерал `Нет шагов`,
2 пробела на уровень вложенности шагов, кодировка UTF-8. Кейсы в пачке идут подряд, каждый с шапки.

```
# **Проверка входа** (ID: 10001)

### Сценарий
1. Открыть страницу входа
```

`--format json` отдаёт ту же модель структурой, `--format html` — самодостаточную страницу. Форматы,
HTML-страница и свой профиль оформления — [docs/format.md](docs/format.md). Использование как
библиотеки — [docs/library.md](docs/library.md).

## Классы ошибок

Результат идёт в стандартный вывод, диагностика — в поток ошибок.

| Класс | Когда | Что происходит |
|---|---|---|
| Код возврата | любой вызов | `0` — успех; `1` — любая ошибка, включая ошибку настроек, с сообщением о причине |
| Запрос AQL | синтаксис не разобран, поле или значение не найдено | сообщение называет операторы и реальные поля проекта; на опечатку — похожее написание |
| Несколько проектов | число `--project` и число `--rql`/`--rql-file` не совпало | отказ с обоими числами, ничего не выгружается |
| Настройки | старая раскладка `config.json`, битый или невалидный `formatFile` | ошибка называет путь и причину, ещё до обращения к TestOps |
| Сеть и сервер TestOps | таймаут, ответ `429` или `5xx`, первый `401` | запрос повторяется с растущей паузой; на `401` — однократное восстановление сессии |

## Скилл для агента

Без скилла агент не знает про инструмент и лезет в API TestOps с вашим токеном. Скилл описывает команды и
прямо запрещает обход; он едет вместе с пакетом: `skills/tt-testops/SKILL.md`.

```bash
tt-testops init                      # спросит, куда ставить, в текущем проекте
tt-testops init C:\путь --for claude # без вопроса: только .claude/skills/
```

| Каталог | Кто читает |
|---|---|
| `.claude/skills/` | Claude Code |
| `.agents/skills/` | Codex, OpenCode |

Команда показывает полный список путей и до подтверждения не создаёт ни одного файла; во все каталоги
сразу не ставит никогда. Глобальной установки нет — скилл живёт в проекте; путь к домашней папке команда отклоняет. Места установки запоминаются в
`~/.tt-testops/skills-registry.json`; после обновления пакета копии обновляются сами при следующем
запуске любой команды. Файлы, добавленные рядом со скиллом вручную, не трогаются.

О новой версии пакета инструмент сообщает раз в сутки при выводе в терминал; обновление —
`tt-testops update`.

## Чего инструмент не делает

- Не пишет в TestOps ничем и никогда — любая команда только читает.
- Не ставит скилл агента глобально: устанавливает только в текущий проект и до подтверждения не создаёт
  ни одного файла.
- Не трогает файлы, добавленные рядом со скиллом вручную.

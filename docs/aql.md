# AQL

Язык запросов TestOps, тот же, что в поиске на сайте. Проект задаётся отдельно — `--project`. Справочник:
[Allure Query Language](https://docs.qameta.io/reference/aql/).

| Запрос | Что найдёт |
|---|---|
| `id in [<ид-1>, <ид-2>]` | конкретные кейсы |
| `tag = "<тег>"` | по тегу |
| `cf["<Поле>"] = "<Значение>"` | по кастомному полю |
| `layer = "E2E"` | по слою; только `=` и `in`, подстрока не поддерживается |
| `automation = false` | ручные кейсы |
| `name ~= "логин"` | по части названия |

Кастомные поля пишутся **только** как `cf["Имя"]`; голое имя TestOps не понимает. Ошиблись в синтаксисе —
инструмент покажет операторы и реальные поля проекта.

**«Ничего не нашлось» и «запрос сломан» — разное.** На опечатку TestOps отвечает нулём кейсов, а не ошибкой.
При пустом ответе продукт сверяет написанное со справочником проекта:

```
$ tt-testops list 'cf["Раздела нет"] = "Раздел А"' --project <ид>
Error: Кейсов не найдено, потому что поля «Раздела нет» в проекте <ид> нет.
Доступно: <Поле-1>, <Поле-2>, …
```

**Написание, отличающееся только начертанием, исправляется само** — регистр, лишние пробелы, латинская
буква внутри кириллического слова. Работает для слоя, имён полей и значений:

```
$ tt-testops list 'layer = "е2е"' --project <ид>
Предупреждение: запрос исправлен: «е2е» → «E2E»
```

Исправление происходит, только когда подходящий вариант единственный; иначе ошибка со списком доступных.
Повтор всегда один. Сверка идёт только при пустом ответе: успешный запрос лишних обращений не стоит.

**Вместо запроса принимается ссылка на фильтр TestOps** — запрос и проект берутся из неё, `--project`
перекрывает. Что AQL выразить не может (например, дерево), не отбрасывается молча.

```bash
tt-testops list 'https://testops/project/<ид>/test-cases?treeId=<дерево>&search=W3si...' --limit 3
```

> [!TIP]
> **PowerShell 5.1 съедает вложенные `"`** — запрос долетит без кавычек. Если в значении есть пробел, строка
> распадётся на несколько запросов и инструмент ответит «Проектов 1, а запросов 2»; если пробела нет —
> TestOps ответит `400`. Одинарные кавычки снаружи не спасают. Экранируйте внутренние кавычки или,
> надёжнее, передайте запрос файлом:
>
> ```powershell
> tt-testops list 'cf[\"<Поле>\"] = \"<Значение>\"' --project <ид-2>
> tt-testops list --rql-file q.txt --project <ид-2>
> ```

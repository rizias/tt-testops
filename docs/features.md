# Возможности

- **Два формата из одного источника** — Markdown и HTML-страница, которая открывается без сети: картинки
  встроены внутрь файла.
- **Вложения файлами** — картинки и файлы кейса лежат на диске в каталоге кейса; ссылка в Markdown ведёт на
  файл, адрес TestOps стоит в ней заголовком.
- **Пометки о состоянии кейса** — старый формат сценария, пустой сценарий. Кейс при
  этом показывается целиком: пометка стоит строкой над сценарием, ничего не прячется.
- **Сценарий автотеста** — у кейса без своих шагов показываются шаги из тестового результата, как на
  карточке TestOps, под строкой «Нет шагов (сценарий взят из автотеста)».
- **Запросы на AQL** — том же языке, что в поиске TestOps. Вместо запроса принимается ссылка на фильтр TestOps
  с любыми его условиями: тегами, кастомными полями, содержимым, сохранённым фильтром.
- **Поиск по фразе в содержимом** — флаг `--text`, как «Содержимое» в поиске TestOps; сочетается с запросом.
- **Несколько проектов в одном документе** — пары «проект — запрос» в одном вызове.
- **Понятный отказ вместо пустоты** — на опечатку в поле или значении инструмент объяснит, чего в проекте
  нет, и подскажет похожее написание, а не вернёт молча ноль кейсов.
- **Локальное хранилище** — данные кейса запрашиваются у сервера при каждой выгрузке; хранилище хранит
  файлы вложений в каталогах кейсов, список деревьев проекта и сессию.
- **Скилл для ИИ-агента** — чтобы агент пользовался инструментом, а не лез в API TestOps с вашим токеном.

# Форматы и свой профиль вывода

## Форматы

| Формат | Где | Что это |
|---|---|---|
| `markdown` | везде | по умолчанию |
| `html` | `case`, `list` | самодостаточная страница: картинки встроены, открывается без сети |
| `raw` | `case` | сырые ответы TestOps без нормализации — когда надо понять, что пришло от сервера |

`raw` — объект с ответами сервера по ключам: `overview` — карточка кейса, `steps` — шаги, `runScenario` — сценарий из
тестового результата (`null`, когда он не запрашивался; пустой список шагов, когда шагов нет; ключа нет, когда получить его не удалось), `comments` — комментарии, `relations` — связи.

Про HTML коротко:

- в шапке блок «Фильтр»: по строке на проект — число кейсов, из чего собрана выборка и кнопка «Открыть в TestOps»;
- разделы и кейсы идут как в TestOps: по названию от А до Я;
- поле отбора по номеру и имени кейса прилипает под панелью управления;
- оформление внутри шага сохраняется (моноширинный, полужирный, курсив, подчёркивание, ссылки, картинки);
- кейсы сложены в дерево разделов, в заголовке — число кейсов внутри; всё свёрнуто, есть «развернуть всё»;
- два вида, переключаются кнопкой: документом и две колонки (слева дерево с отбором по номеру и имени,
  справа кейс); граница колонок двигается, выбор и ширина запоминаются;
- в заголовке кейса — тип, кликабельный номер в TestOps, состояние сценария, число комментариев, кнопка
  копирования имени со ссылкой;
- щелчок по картинке открывает её поверх страницы, повторный — в натуральную величину;
- комментарии показываются вместе с картинками внутри них;
- картинки и файлы встраиваются из тех же файлов вложений в каталоге кейса, что и у Markdown;
- без `--out` файл пишется сам, путь печатается в служебный вывод.

`Статус в TestOps` ставит человек (`Manual`, `Automated`, `Reviewed`, `Active`), `Автотест` проставляет
TestOps сам, когда автотест отчитался: намерение и факт могут разойтись.

## Свой формат вывода

Профиль — JSON, частично переопределяющий стандартный Markdown; пересборка не нужна.

```json
{
  "customFields": {
    "hide": ["<Поле-3>"],
    "rename": { "<Поле>": "Раздел" },
    "order": ["<Поле-1>", "<Поле-2>"]
  },
  "steps": { "numbered": false, "expandAttachments": true }
}
```

```bash
TT_TESTOPS_FORMAT_FILE=./my-format.json tt-testops case <ид-кейса>
```

Тот же файл можно указать полем `formatFile` в `profile.json`. Профиль читается при каждом запуске и
глубоко объединяется со стандартным. Несуществующий файл, невалидный JSON или неверный тип поля — ошибка
до обращения к TestOps.

Путь собирается только из полей рабочего дерева; остальные заполненные поля показываются атрибутами, и
`hide` / `rename` / `order` управляют только ими.

### Рендер шагов

- нумерация как в отчёте TestOps: `1. 2. …`, на каждом уровне с единицы (`steps.numbered: false` → маркеры `-`);
  номер получает каждый шаг, как в TestOps, в том числе шаг без текста с вложенными шагами или ожидаемым
  результатом, и шаг, текст которого начинается с `-`;
- вложенность — отступом стандартного Markdown, перед вложенными шагами пустая строка;
- текст кейса выводится как пришёл из TestOps, символ в символ: пробелы, переводы строк и пустые строки
  сохраняются; инструмент добавляет только номера шагов, отступы вложенности, заголовки и подписи;
- ожидаемый результат — после пустой строки, под шагом, пункты пронумерованы;
- вложение шага с текстом — своим текстом; картинка или файл — строкой-ссылкой под текстом шага;
- текстовые файлы шага выводятся своим содержимым (`steps.expandAttachments: false` отключает для файлов, которые
  не Markdown); все URL абсолютные;
- ссылка на вложение — картинку или файл, в тексте и на шаге — ведёт на локальный файл в каталоге кейса, адрес
  TestOps стоит в ней заголовком: `![](<путь> "<адрес>")`, `[<имя>](<путь> "<адрес>")`; вложение, которое не
  скачалось, остаётся ссылкой на адрес TestOps;
- структура TestOps не «исправляется»: если ожидаемый результат заведён отдельным шагом, так он и показан.

### Сценарий из автотеста

У кейса без своих шагов сценарий берётся из тестового результата — это те же шаги, что карточка TestOps
показывает с подписью «из тестового результата». Вложения этих шагов не выводятся: они принадлежат запуску.
Над шагами стоит строка, в HTML она над списком и в нумерацию не входит:

```markdown
### Сценарий
> ⚠️ **Нет шагов** (сценарий взят из автотеста)
1. <шаг>

    1. <вложенный шаг>
```

Текст строки задаёт ключ профиля `warnings.autotestScenario`.
Пометка «Пустой сценарий» у такого кейса остаётся.
